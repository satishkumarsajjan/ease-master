## 1. The Satisium Discovery Philosophy (The 3-Engine Model)

In modern web development, search has fragmented into three distinct discovery ecosystems. An architectural template must be optimized for all three simultaneously:

```
┌────────────────────────────────────────────────────────────────────────┐
│                   THE 3-TIER DISCOVERY TRIFECTA                        │
├──────────────┬─────────────────────────────────────────────────────────┤
│ 1. SEO       │ Traditional Search (Google, Bing, DuckDuckGo)          │
│              │ Intent-driven organic keyword ranking & high-intent jobs│
├──────────────┼─────────────────────────────────────────────────────────┤
│ 2. AEO       │ Answer Engines (Perplexity, Google AI Overviews, Apple) │
│              │ Extractive AI synthesis citing your tool as the source  │
├──────────────┼─────────────────────────────────────────────────────────┤
│ 3. GEO       │ Generative Engines (Cursor, Claude, ChatGPT, Copilot)   │
│              │ In-editor developer assistants recommending your code   │
└──────────────┴─────────────────────────────────────────────────────────┘
```

### Domain & Branding Architecture Disclaimer (The Acquirability Invariant)

To protect the premium developer identity of the core brand and ensure the Venture Apps remain highly acquirable, strict domain isolation is enforced:

- **The Design Ecosystem (Part I):** ALL tools, studios, and libraries in this pillar live on subdomains of the master brand: **`*.satisium.com`** (e.g., `type.satisium.com`, `ui.satisium.com`, `board.satisium.com`, `ship.satisium.com`). This compounds organic backlinks, topical authority, and domain trust back to the core developer platform.
- **The Venture Apps & Moonshots (Parts II & III):** ALL consumer and B2B SaaS apps have completely independent, isolated domain names (e.g., `mosaic.app`, `kudosboard.io`, `signal.co`, `sprintui.com`, `spatialcinema.com`). **They will never carry the `.satisium.com` URL.** This guarantees that when a venture app is acquired, the acquirer receives a clean asset with isolated domains, cookies, auth, and brand equity without entangling `satisium.com`.

### The Dual-Intent Search Architecture

The Grand Ecosystem spans two distinctly different search behaviors:

1. **Design Micro-Studios (Pillar: `design`):** Users have **immediate technical utility intent**. They are in the middle of a coding session and search for an algorithm, calculator, or snippet (e.g., `oklch palette generator`). They demand instant interactivity with zero login barriers. SEO and AEO must prioritize rapid tool execution and clean code export.
2. **Labs SaaS Platforms (Pillar: `labs`):** Users have **workflow or event solution intent**. They want to solve a human problem (e.g., `real-time wedding photo guest upload wall`). They evaluate features, pricing tiers, social proof, and workflows. SEO and AEO must prioritize benefit-driven positioning, FAQ accordions, and frictionless onboarding.

### The 4 Components Google Evaluates:

1. **Google Site Name Attribution (Top Header):**
   - Google displays the verified brand name (`Satisium UI` or `Color Studio`) above the URL rather than displaying the raw domain string.
   - **Mechanism:** Handled via `schema.org/WebSite` JSON-LD declaring `name` and `alternateName`.
2. **Authoritative Page Title & Meta Snippet:**
   - High-contrast, non-truncated primary link with punchy value proposition.
   - **Mechanism:** Strictly capped at ≤ 60 characters for titles and 120–155 characters for descriptions.
3. **Expanded Organic Sitelinks (The Indented Grid):**
   - 4 to 6 prominent sub-pages rendered directly below the main search result.
   - **Mechanism:** Handled via clean semantic `<nav>` anchors, `schema.org/SiteNavigationElement` JSON-LD, and high priority scores in `sitemap.xml`.
4. **Hierarchical Breadcrumbs:**
   - Google renders clean visual breadcrumbs (`ui.satisium.com › Docs › Components`) instead of raw URL paths (`ui.satisium.com/docs/components/button`).
   - **Mechanism:** Handled via `schema.org/BreadcrumbList` JSON-LD.

### The Direct-Answer Copywriting Formula for AEO

To win citations in **Perplexity, Google AI Overviews, and Apple Intelligence**, landing pages and documentation must use the **Extractive Answer Pattern**:

1. **Heading Framing:** Frame section headers as explicit user queries:
   - `## How does fluid clamp() typography work?`
   - `## What makes OKLCH superior to standard HSL?`
   - `## How do guests upload live photos to Mosaic without an app?`
2. **The 45-Word Extractive Answer Rule:** Immediately follow the heading with a single, standalone paragraph of **35 to 50 words** containing zero fluff:
   > _"Fluid clamp typography uses the CSS clamp(min, preferred, max) function combined with viewport width (vw) units to smoothly scale font sizes between mobile and desktop viewports without relying on discrete media query breakpoints."_
3. **The Immediate Technical Anchor:** Place a clean code block, formula, interactive widget, or visual step directly below the definition.

- **Why this works:** Large Language Models use extractive summarizers. When an AI crawler indexes this pattern, it lifts the 45-word definition verbatim and cites your tool as the primary source URL.

## 4. Schema.org Knowledge Graph Specification (JSON-LD)

> [!IMPORTANT]
> **ARCHITECTURAL INVARIANT: CODE IMPLEMENTATION vs. EVALUATED SEARCH ENGINE OUTPUT**  
> **NEVER hardcode static tool names, URLs, or schema blocks into your application layouts.**  
> In the Satisium Starter, all schemas are **dynamically assembled** from `config/site.ts` (`PRODUCT`, `AUTHOR`, and `SITE_URL`). When spinning up a new product (e.g. Type Studio, Mosaic, or Color Studio), developers and AI agents only edit `config/site.ts` (or author `PRODUCT_SPEC.md`). The template dynamically renders the JSON-LD schemas in `app/layout.tsx`.
>
> Every schema below is documented with:
>
> 1. **Dynamic TypeScript Implementation:** The exact code in `app/layout.tsx` (using template variables).
> 2. **Evaluated Output:** What Googlebot, Perplexity, and Schema Validators parse after server-side rendering.

## 5. Title, Meta, and Truncation Invariants

Search engines calculate title and description truncation based on **rendered pixel width** (typically 600px for desktop titles, ~960px for descriptions).

### Mathematical Length Guardrails

- **`<title>` Ceiling:** **Strictly ≤ 60 characters.** Any title longer than 60 characters gets truncated with an ellipsis (`...`), diluting brand credibility.
  - _Formula:_ `[Tool Name] — [High-Intent Job] | Satisium`
  - _Example:_ `Color Studio — OKLCH Palette Generator | Satisium` (50 chars) ✅
- **`<meta name="description">` Ceiling:** **Strictly 120 to 155 characters.**
  - Shorter than 120 characters under-utilizes valuable search real estate.
  - Longer than 155 characters gets cut off mid-sentence.
  - _Formula:_ `[Action Verb] + [Specific Value Delivery] + [Key Technology/Compliance].`
  - _Example:_ `Generate WCAG-compliant accessible OKLCH and HSL variable matrices. Export directly into Tailwind CSS v4 themes in one click.` (126 chars) ✅

### Dynamic Social Cards (`/api/og`)

Social click-through rate (CTR) on Twitter/X, LinkedIn, Discord, and Reddit directly feeds organic search rank via referral volume.

- Every route automatically renders a **1200×630px Edge SVG/PNG card** via `/api/og`.
- Must display the page title, category badge (`STUDIO`, `DOCS`, `KIT`), and clean brand background.
- OpenGraph tags must declare:
  ```html
  <meta property="og:image:width" content="1200" />
  <meta property="og:image:height" content="630" />
  <meta name="twitter:card" content="summary_large_image" />
  ```

## 6. Machine-Readable AI Surfaces (`llms.txt` & Robots Protocol)

Modern AI assistants (Cursor, ChatGPT, Claude, Perplexity) do not want to parse client-side React bundles. They ingest raw markdown.

### The Dual-Surface Architecture

Every product in the umbrella maintains a dual surface:

1. **Interactive Human Surface:** Rich SSR React components at `/`, `/app`, `/docs`.
2. **Machine Markdown Surface:** Produced automatically before every build via `scripts/build-llms.mjs`:
   - **`/llms.txt`:** The curated index file AI agents look for first.
   - **`/llms-full.txt`:** The entire documentation and API surface concatenated into a single file for 1-shot LLM context injection.
   - **`/llms/*.md`:** Clean markdown files matching every documentation URL.

### AI Robot Directives in `app/robots.ts`

To ensure generative engines index our documentation while protecting private API endpoints:

```ts
// app/robots.ts
```

## 7. The Subdomain Authority Mesh (Inter-Ecosystem Link Graph)

Google evaluates websites using **Topical Authority** and internal link structure.

### The Topical Clustering Principle

When 25 subdomains exist as isolated silos, each must build domain authority from zero. But when all subdomains actively link to each other:

1. **Ecosystem Directory in Footers:** Every tool includes a clean directory in the footer linking to its sister tools:
   `"Part of Satisium Design: [Color Studio](https://color.satisium.com) · [Type Studio](https://type.satisium.com) · [Shadow Studio](https://shadow.satisium.com)"`
2. **Zero-Phantom Link Invariant:** **Never link to tools that are not yet built or live.** Dead links (`404` or `ERR_NAME_NOT_RESOLVED`) heavily penalize domain health. Only live, verified products may be linked.
3. **Canonical URLs:** Every page must specify its own absolute canonical URL via `lib/metadata.ts` to prevent duplicate indexing across tracking parameters:
   ```html
   <link rel="canonical" href="https://ui.satisium.com/docs/components" />
   ```

## 8. Google Search Console & Indexing Infrastructure

### The One-Time DNS-Level Domain Verification

Instead of verifying 25 individual subdomains separately, Satisium uses **Google Search Console DNS Verification**:

1. Add a single DNS TXT record for **`satisium.com`** in your domain registrar / Cloudflare dashboard.
2. In Google Search Console, create a **Domain Property** for `satisium.com`.
3. **Result:** Google automatically verifies, indexes, and aggregates performance telemetry for `satisium.com` and **every current and future subdomain** (`*.satisium.com`) in a single unified dashboard forever.

### Dynamic XML Sitemap Priority (`app/sitemap.ts`)

Google allocates crawl budget based on sitemap priority weighting:

- **Priority 1.0 (Daily):** Root landing page (`https://<tool>.satisium.com`).
- **Priority 0.9 (Weekly):** Workstation application (`/app`) and primary documentation hub (`/docs`).
- **Priority 0.8 (Weekly):** Core sitelink candidates (`/docs/components`, `/docs/installation`).
- **Priority 0.6 (Monthly):** Deep documentation articles and changelogs.

## 9. The Pre-Launch SEO Quality Gate

Before any tool is deployed to production, it must pass the **3 Pre-Flight Gates**:

### Gate 1: Google Official Rich Results Test

- Open **[Google Rich Results Test](https://search.google.com/test/rich-results)**.
- Test the deployment URL or raw HTML output.
- **Pass Criteria:** Valid `WebSite`, `WebApplication`, `SiteNavigationElement`, and `BreadcrumbList` schemas with **0 errors and 0 warnings**.

### Gate 2: Core Web Vitals (CWV) Performance Floor

Google's ranking algorithm incorporates page experience signals:

- **Largest Contentful Paint (LCP):** < 2.5 seconds.
- **Interaction to Next Paint (INP):** < 200 milliseconds.
- **Cumulative Layout Shift (CLS):** < 0.1 (achieved by Next.js font and image optimization).

### Gate 3: Automated Machine Check (`pnpm doctor`)

- Execute `pnpm doctor`.
- Verifies zero broken routes, asset presence, and strict domain compliance (`satisium.com`).
