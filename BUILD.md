## 1. The session protocol

Every session runs the same five steps. Do not improvise.

1. **Load narrow.** Read only the sections listed for your session in §2, plus this file. Never load
   both specs end-to-end — you do not need them and they will crowd out the code.
2. **Plan in five lines.** List the files you will create or modify, in order. State it, then proceed.
3. **Execute one phase at a time.** Use the exact `[COPY]` commands. Apply **every** numbered
   adaptation edit — they exist because the reference is library-specific.
4. **Validate.** Run the phase's validation block from `starter-template.md` and paste the raw
   output. If it fails twice: `git reset --hard HEAD`, report, and stop. **Never** continue into the
   next phase with a broken previous one.
5. **Commit, stop, report.** Commit with the phase message from §2, then stop and post the report
   below. Stopping is required — the human approves each checkpoint.

### 1.1 Report template (use verbatim)

```
PHASE <n> — <name>
Status:        DONE | BLOCKED
Files:         created <n>, modified <n>   (list the important ones)
Validation:    <paste the exact command output>
Deviations:    <none — or what the spec got wrong and the doc edit you made in this commit>
Next phase:    ready | blocked by <reason>
```

## 5. Hard rules for the agent

1. **Zero-key boot.** With an empty `.env.local` the app boots, builds and passes tests. If you make
   something require a key, you have broken the template.
2. **Tokens only.** No hex/rgb/`text-gray-*`. Radius, type and motion rules: `component-kit.md` §2.3.
3. **Routes from `lib/routes.ts`; nav from `lib/nav.ts`.** No literal `href` in components.
4. **Two libraries, never mixed.** `registry/**` is distributed; `components/**` is internal.
5. **Additive modules only.** A module may add files/env/CSP origins — never edit an upstream file.
6. **Docs ship with the feature** (`content/docs/**`), and the ⌘K/hotkey registries stay updated.
7. **Analytics never blocks anything** and never carries PII. Add events to the §18.6 table.
8. **Motion respects the user** — `MotionConfig reducedMotion="user"` + the CSS block (§21.1).
   8a. **Two docs layouts, chosen by the developer.** `spatial` (card shift) or `three-pane`
   (borderless sidebar | article | optional rail), set in `NEXT_PUBLIC_DOCS_LAYOUT` and baked
   into the build. Never add a third variant, a runtime switcher or a query parameter —
   visitors have no control over it. `M` is the only navigation shortcut; there is no `⌘B`.
9. **Label every icon-only control** with `aria-label` + `title`.
   9a. **No borders, no shadows — anywhere.** Separation comes from the achromatic surface
   ramp (`--muted` screen, `--background` panes, `--accent` raised) plus spacing. Every
   `--shadow-*` token in `globals.css` is `none`, so a stray `shadow-*` class renders nothing.
   Radius is the only shape signal and comes from `--radius`. `border-0` / `border-none` are
   resets, not chrome. **One carve-out: `focus-visible:ring-*` stays** — WCAG 2.2 (2.4.11)
   requires a visible focus indicator, and a ring is state, not chrome. `pnpm doctor` fails
   the build if `border-*`, `shadow-*` or `drop-shadow-*` appears in `components/docs/**` or
   `components/previewer/**`.
   9b. **Derive layout widths; never choose them.** `--docs-measure` (the ~700px reading
   measure, 45-75 characters) is the anchor and every pane width, the article cap and each
   breakpoint are solved backwards from it. Rails are `clamp()`, never fixed pixels — a fixed
   rail makes the article `viewport - constant`, i.e. a rubber band. The acceptance test is
   that the article's width does not change as the window grows: rails absorb the growth,
   the article holds still. `pnpm e2e` asserts the measure band at 1024/1280/1440/1920; an
   unasserted invariant is just a comment.
10. **`pnpm verify` before every commit**; conventional commit messages or commitlint rejects you.

**Two failure modes to never commit**

- **Phase stacking** — never start phase N+1 while phase N's validation fails. Revert instead.
- **Silent deviation** — if you cannot do exactly what the doc says, stop and report rather than
  inventing a variant. The doc is the contract; a wrong doc gets fixed in the same commit.

## 10. Authority order

When two sources disagree, the higher one wins, and the lower one gets fixed **in the same commit**:

1. `BUILD.md` — process (sessions, checkpoints, rules)
2. `starter-template.md` — the shell specification
3. `component-kit.md` — the template library specification
4. `content/docs/**` — documented behaviour
5. the code

If reality (the reference repo, a library version, a platform change) contradicts a specification,
stop and report with the `§3.4` prompt. Never guess silently.
